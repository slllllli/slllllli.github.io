大多数论文速读会把论证压成几条要点。读完之后，你知道作者声称了什么，却不知道这个结论为什么并不显然、哪一个设计选择真正起了作用，以及这套想法在哪里悄悄失效。

「论文解构室」想做的事情慢一点。

<!-- more -->

## 为什么还要写论文博客？

我总在以同一种方式遗忘论文：摘要还能背出来，论证却重建不了。如果有人问，某个架构**为什么**取代了前一个，我往往只能给出一个口号，而不是一套机制。

所以这份笔记围绕一个简单的检验展开：读完一篇笔记之后，你应该能不看摘要，向同事讲清楚这篇论文。这意味着依次讲出问题、关键动作、证据和代价。

## 一篇笔记如何展开

每篇分析都经过四遍。结构刻意重复，这样即使论文主题差异很大，笔记之间仍然可以比较。

### 问题

在这篇论文之前，真正难的是什么？不是“作者识别出了什么空白”，而是实践者撞上了什么瓶颈。好的答案通常包含一个约束：串行计算、标注数据、显存、优化，或者评测。

### 机制

核心想法是什么？要精确到可以实现。公式与张量形状在这里才有意义。如果一张图无法翻译成一个形状或一次运算，它大概只是装饰。

### 证据

哪些实验真正支撑了结论？消融实验尤其有用，因为它隔离了某个设计选择。一个漂亮的 headline 数字告诉你“有效”；一个构造良好的消融告诉你**是什么**有效。

### 局限

论证在哪里停下？每篇有影响力的论文都有边界条件，后续工作往往就住在这些边界里。指出局限不是批评，而是理解一个想法为何扩散的一部分。

## 一个小例子：《Attention Is All You Need》

2017 年的 Transformer 论文是一个很好的测试案例：它的核心主张既容易陈述，也容易被误读。它不是“注意力很好”，而是**仅靠注意力就足够**支撑一个序列模型，不需要循环，也不需要卷积。

### 瓶颈

在 Transformer 之前，主流的序列模型——RNN 与 LSTM——逐个 token 处理序列。位置 $t$ 的隐状态依赖 $t-1$ 的状态，因此训练无法在序列维度上完全并行。两个相距很远的 token 之间的路径长度也会随距离增长，这让长程依赖变得昂贵。

这就是论文攻击的约束：不是循环本身在原则上不好，而是它在长序列、大数据这个场景下的代价。

### 关键动作

注意力机制早已存在。Transformer 的动作是彻底移除循环，让注意力来承载序列。每一层都同时观察所有 token，为每个 token 计算新的表示。

这个操作可以理解为一次软检索。每个 token 发出一个 **query**，每个 token 暴露一个 **key** 和一个 **value**。query 与 key 的匹配程度，决定对应的 value 有多少流入输出。

### 公式

$$
\operatorname{Attention}(Q,K,V)
= \operatorname{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
$$

其中 $Q$、$K$、$V$ 是输入经过学习的线性投影。$QK^{\top}$ 为每一对 query 与 key 打分；softmax 把分数变成权重；再乘以 $V$，得到加权混合。$\sqrt{d_k}$ 用来避免点积随维度增长而过大，否则 softmax 会进入饱和区。

多头注意力用不同的投影并行重复这一操作，再拼接结果。多个头不是多个模型，而是同一层里的不同子空间；论文的消融实验也暗示，多个头比一个更大的头更有用。

### 为什么有效

有三个后果值得记住：

| 性质 | 循环 | 自注意力 |
| --- | --- | --- |
| 每层串行操作数 | $O(n)$ | $O(1)$ |
| token 之间的最长路径 | $O(n)$ | $O(1)$ |
| 每层计算代价 | $O(n d^2)$ | $O(n^2 d)$ |

前两行是概念上的胜利：信息可以在一步之内跨越很远，层内计算可以并行。第三行是账单：注意力对序列长度是二次的。更多的并行、更短的路径，代价是随 $n^2$ 增长的显存——这才是这篇论文真正的交易。

### 它在哪里停下

Transformer 并没有解决长上下文。它把瓶颈从串行计算挪到了注意力显存。它同时继承了位置编码的依赖，因为注意力本身对排列是不变的。后来关于高效注意力、状态空间模型和检索的工作，很大程度上都在与这个 trade-off 争论。

这正是这份笔记关心的论证方式：不是判断一篇论文是否“重要”，而是它究竟改变了什么，又留下了什么。

## 这里不做什么

它不是论文的替代品，也不是资讯流、排行榜或“中立”的结论。我写这些是为了更理解材料，因此难免出错，欢迎指正。
